# 1.5.8 — 无句末标点的步骤被整段丢弃

## 症状

有些句子完全不朗读。典型形态是以冒号结尾、不含任何句末标点的引导句：

> 命令执行失败，改用另一种方式绕过：

这类句子正是模型在调用工具前写的过渡语，出现频率不低。

## 成因

1.5.7 的补读条件要求「上一次游标大于 0」。但这类 step 的文本里根本没有句末标点，
`takeSpeakable` 从不放行，游标**始终为 0**，条件永远不成立，整段在步骤切换时被
静默丢弃。

## 修复

不再依赖游标是否推进过，改为直接判断文本源是否被整体替换：游标大于 0 时沿用原
判断；游标为 0 时看新文本是否仍以旧文本为前缀——是则同一步骤在增长，不是则文本源
已替换，整个未读部分都要补读。

```js
if (previous !== undefined && previous !== null) {
  const replaced = previous.cursor > 0
    ? cursor === 0
    : previous.text.length > 0 && !info.text.startsWith(previous.text)
  if (replaced) {
    const rest = previous.text.slice(previous.cursor)
    if (toSpeechText(rest).length > 0) {
      enqueueAuto(sessionId + AUTO_SEP + info.turn + AUTO_SEP + 'tail' + AUTO_SEP + previous.cursor, rest)
    }
  }
}
```

至此五处修复完成，形成「文本源被替换时先补读残留，再读新 step」的完整逻辑：

- 残留有两种形态，都覆盖到了：
  - 已经读了一部分后才被替换（游标大于 0，回落到 0）
  - 一个字都没读就被替换（游标始终为 0，靠前缀比较识别）
- 同一步骤内文本只是增长时，新文本仍以旧文本为前缀，`startsWith` 为真，因此不会
  提前补读。
