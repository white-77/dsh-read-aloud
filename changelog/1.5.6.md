# 1.5.6 — 重启后重读历史回复

本版本包含两处相关修复：先持久化已读记录，随后发现 arming 时机仍有漏洞，一并修正。

## 症状

重启 Harness 后，上一次已经读过的回复被从头再读一遍。

## 成因

三处状态的生命周期不一致：

| 状态 | 存储位置 | 重启后 |
|---|---|---|
| 自动朗读开关 | `localStorage` | 保留（仍是「开」） |
| `readTurns`（已读 Turn） | 内存 Set | **清空** |
| `armSession()`（标记历史为已读） | — | 只在点击开关时调用 |

重启后开关是开的、已读记录是空的，屏幕上那条回复被当作新消息读出。

## 修复一：已读记录持久化

1. 已读记录持久化到 `localStorage`（键 `dsh-read-aloud:read`），启动时恢复。
   每会话最多保留 40 条，防止无限增长。
2. 新增 `markRead()` 统一「写内存 + 落盘」。
3. 在 `handleAuto` 两种模式汇合处加统一守卫：

   ```js
   if (info.closed && readTurns.has(key)) return
   ```

   原先只有 final 模式检查「是否已读」，**流式模式会直接念历史**。

## 修复二：首帧空 snapshot 导致空 arm

仅做上面的持久化还不够——重启后依然会重读。原因是页面刚打开时 Chat snapshot 是
空的（历史尚未加载），此时若把会话标记为「已 arm」，却没有标记任何内容为已读，
等历史随后到达，那些回复仍然是「未读」。

新增 `ensureArmed()`，只有当 snapshot 至少含 1 个 Turn 时才 arm —— 那一刻历史才是
可知的：

```js
const ensureArmed = (sessionId, snapshot) => {
  if (armedSessions.has(sessionId)) return
  if (orderedTurns(snapshot).length === 0) return
  armedSessions.add(sessionId)
  armSession(sessionId, snapshot)
}
```

`setAuto()` 在空快照上点开关时同样不算 arm，留待历史到达。

## 行为变化

重启后屏幕上已有的内容一律视为历史，**不再自动朗读**。

这是有意为之：「读到哪里」这个进度不落盘，重启后无法可靠恢复；与其猜一个位置接着
念（可能念串、跳字），不如不念。想听那条没读完的回复，点它下面的喇叭图标手动朗读
——手动路径 `readItem` 与自动朗读 `handleAuto` 完全独立，不受影响。
