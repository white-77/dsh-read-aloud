# 1.5.10 — 表格内容被丢弃、回复最后一句不朗读

## 症状

- 回复里有表格时，表格内容完全不朗读。
- 回复最后一句偶尔不读。报告实例的最后一句是
  「需要我帮你把 nacos-client 升到 2.5.5，并先跑一遍依赖冲突检查吗？」。

## 成因

两处都在 `toSpeechText` 的 markdown 清洗环节。

**其一：表格整行被替换成空格。**

```js
text = text.replace(/^\s*\|.*\|\s*$/gm, ' ')
```

这是最直接的丢弃：表格每一行都匹配 `|...|`，被整体换成空格。表格里的数据既
没被念出来，表格本身也不留任何痕迹。若回复**以表格结尾**，表现就像「最后一句
不读」。

**其二：`markRead` 早于「是否可朗读」的判断。**

`final` 分支原先无条件 `markRead` 再入队：

```js
markRead(sessionId, info.turn)
enqueueAuto(sessionId + AUTO_SEP + info.turn, info.text)
```

而 `speak()` 在清洗后文本为空时返回 `false`，这次播放不会发生；但 Turn 已被记为
已读，之后每个快照都会被 `if (info.closed && readTurns.has(key)) return` 拦下，
这段内容再无机会朗读。流式分支同样在检查之前调用了 `markRead`。

## 修复

**表格**：新增 `tablesToSpeech`，把表格行改写为可朗读的句子，分隔行
（`|---|---|`）丢弃：

```
| 版本 | 大小 |
|---|---|
| 1.5.9 | 94616 字节 |
```

朗读为：

```
版本，大小。1.5.9，94616 字节。
```

每个数据行成为一句，单元格以「，」连接、句尾补「。」，与正文的朗读节奏一致。

**已读标记**：把 `markRead` 移到「确认有内容可读」之后。

```js
if (toSpeechText(info.text).length === 0) return
markRead(sessionId, info.turn)
enqueueAuto(...)
```

流式分支同样改为只在 `speakable.length > 0 || cursor > 0` 时才标记已读。

## 测试方式的变更

这里是更重要的改动：**测试不再替身 `toSpeechText`。**

此前 `buildSandbox` 注入的是 `toSpeechText: (s) => s`，所有测试都在未清洗的原始
文本上运行。这掩盖了整整一类缺陷——凡是在 markdown 清洗里丢内容的问题，测试都
看不见。表格问题能存活到 1.5.9 就是因为它藏在这个替身后面。

现在 `FUNCS` 直接抽取 `client.js` 里的 `tablesToSpeech` 与 `toSpeechText`，测试跑的
就是真实的转换链。

新增 5 项测试，共 **37 项**全部通过：

- `toSpeechText` 保留表格单元格内容
- 回复以表格结尾时表格仍被朗读
- 表格中的拉丁词不被丢弃
- 回复最后一句（含拉丁缩写）被朗读
- 回复以表格结尾且表格含最后一句
