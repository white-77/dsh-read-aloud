# 1.5.9 — 播放队列中断导致后续整段不朗读

## 症状

回复读到某一句之后突然停止，后面的所有内容都不再朗读。

## 成因

两处「失败即放弃」的实现叠加，都发生在 `handleAuto` 之后的下游播放环节。

**其一：单句失败终止整段播放。**

`playItems` 的 `step()` 在 `catch` 里直接调用 `reset(message)`：

```js
} catch (error) {
  if (name === 'AbortError') return
  reset(String((error && error.message) || 'read-error'))
}
```

`reset` 会把 `playing` 置回 false 并结束这一轮播放。只要有一句合成或播放抛错
（网络抖动、`/speech` 瞬时失败、音频解码异常），**剩余所有句子一并丢弃**。

**其二：无法开始的队列条目卡死后续条目。**

`drainAuto` 出队后无条件 `return`，但 `speak()` 在文本清洗后为空、或没有可用引擎时
返回 `false`——这次播放根本没有开始，`playing` 一直是 false。而队列泵只由
`playing` 变 false 的事件触发，于是没有任何事件再来推动队列，**后续条目永久滞留**。

`readItem` 的返回值此前被完全忽略。

## 修复

**playItems**：单句失败改为跳过并继续；连续失败达 3 次才判定引擎本身不可用，
此时仍会终止，但把首个错误上报给界面，不会静默失败。

```js
} catch (error) {
  if (disposed || myToken !== token) return
  const name = error && error.name ? String(error.name) : ''
  if (name === 'AbortError') return
  failures += 1
  if (firstFailure === null) firstFailure = String((error && error.message) || 'read-error')
  if (failures >= 3) { reset(firstFailure); return }
  index += 1
  step()
}
```

成功后 `failures` 归零，因此偶发失败不会累积到阈值。

**drainAuto**：检查 `readItem` 的返回值，没开始就继续取下一个，直到真正开始播放
或队列取空。

```js
const started = readItem(next.id, next.text)
if (started) return
```

## 为什么之前的测试没抓到

原有 28 项测试覆盖 `handleAuto` 的文本选择与游标逻辑，但：

- `enqueueAuto` 被简化成直接记录文本，绕过了真实队列
- `player.speak` 未被建模，无法表达「返回 false」
- `playItems` 的异步错误路径完全未覆盖

本次新增 4 项测试，用真实的 `drainAuto` 加可控的 `readItem` 钩子覆盖队列行为。
