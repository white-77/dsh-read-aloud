# 1.5.7 — 步骤切换时未读完的尾部被丢弃

## 症状

一句话读到句号就停了，句号后面那半句再也没读。例如：

> 命令执行失败。改用另一种方式绕过：

只听得到「命令执行失败。」，「改用另一种方式绕过：」消失。

## 成因

`takeSpeakable` 在流式模式下只朗读到**最后一个句末标点**为止，剩余的半句留待下次
快照补全。但这个假设只在「文本单调增长」时成立。

模型调用工具时，当前 step 就此结束，下一个 step 的文本**整体替换**掉它——那半句
永远不会被补全，直接丢失。1.5.5 的 `streamCursorFor` 正确地让游标归零，却也等于
放弃了那段残留。

## 修复

检测到文本源被替换时，先把上一段未朗读的尾部补读出来，再读新 step：

```js
if (cursor === 0 && previous !== undefined && previous !== null && previous.cursor > 0) {
  const tail = previous.text.slice(previous.cursor)
  if (toSpeechText(tail).length > 0) {
    enqueueAuto(sessionId + AUTO_SEP + info.turn + AUTO_SEP + 'tail' + AUTO_SEP + previous.cursor, tail)
  }
}
```

队列是 FIFO，尾部先于新 step 播出，顺序与原文一致；补读后游标立即被替换为新文本的
状态，因此同一段尾部不会重复朗读。

## 已知局限

本版本只在「上一次游标大于 0」时触发补读，即该 step 已经通过 `takeSpeakable` 读过
一部分。若某个 step 从头到尾都没有句末标点，游标始终为 0，本条件不成立，整段仍会
丢失——该情形在 1.5.8 修复。
